# Bug Register

| ID | Severity | Category | File | Function | Finding | Evidence | Risk | Recommended Action |
| -- | -------- | -------- | ---- | -------- | ------- | -------- | ---- | ------------------ |
| 01 | MEDIUM | Scheduler | `timer.cpp` | `onTimer()` | `RUNNING_TICK_COUNTER` resets to 0 but `LAST_*_TIME_VALUE` also resets to 0. A tick might be lost or offset calculation misbehaves on rollover limit. | Rollback logic: `ssl_timer.RUNNING_TICK_COUNTER = 0U; LAST_*_TIME_VALUE = 0;` | Drift or missing a scheduled event every 10 mins. | Use modulo arithmetic or improve rollover threshold tracking without zeroing the base unless synced safely. |
| 02 | MEDIUM | Refactor | `main.cpp` / `gsm.cpp` | `gsmSendJSON()` | Duplicated implementation of GSM logic. `main.cpp` implements `gsmSendJSON` while `gsm.cpp` implements `tcpSend`. | `main.cpp` line 403 vs `gsm.cpp` functions. | Inconsistency. | Standardize GSM calls to use the proven `gsm.cpp` library or keep `main.cpp`'s implementation if it's the intended one. Needs careful tracing. |
| 03 | HIGH | Memory | `main.cpp` | `buildGSM_JSON()` | Extensive repeated string concatenation (`json += ...`). Arduino `String` fragmentation is likely over days of continuous operation. | `String json = "{"; json += "\"device_id...` | Heap fragmentation, `String` exhaustion, and memory leaks. | Use `String::reserve()` upfront with a calculated size, or refactor to `snprintf` with a static char buffer. |
| 04 | HIGH | Security | `main.cpp` | `handleSet()` | Potential buffer overflow or unsafe parsing in `server.arg()`. Changes are written to NVS via `Preferences` without ensuring the length is within NVS limits. | `save_device_id_NVS(server.arg("device_id"));` | NVS corruption or watchdog reset on excessively large inputs. | Enforce length constraints before saving to NVS. |
| 05 | MEDIUM | Sensor | `gas_sensor.cpp` | `gas_sensor_task()` | Hardcoded `delay()` calls or blocking serial reads. Blocking calls inside sensors delay the `loop()`, starving the Web Server and WDT. | `delay(100);` | High impact on main loop. | Use non-blocking timeouts (`millis()`). |
| 06 | MEDIUM | Sensor | `data_structure.h` | global | Values are initialized to `0.0f` but there is no invalidation mechanism (e.g., `valid` flag or `last_update` timestamp per sensor). If a sensor fails, `0.0f` or the last known good value is endlessly transmitted. | Missing validity mechanism. | Transmitting stale/invalid data. | We can add a basic validity flag or reset mechanism to `weather_data`. |
| 07 | HIGH | Security | `main.cpp` | `handleSet()` | Missing authentication validation. `/set` does not seem to verify if the user is authenticated. | Missing `if (authenticated)` check. | Unauthorized modification of configuration. | If confirmed, implement lightweight authentication checking on sensitive endpoints. |
